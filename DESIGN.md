# Design Document

## 1. Архитектура

Проект разделён на игровую логику и пользовательский интерфейс.

Игровая логика находится в `src/game`. Основные функции не зависят от DOM.

Пользовательский интерфейс находится в `src/main.ts` и отвечает за отображение состояния игры, обработку событий и сохранение результатов.

Такое разделение позволяет тестировать игровую логику независимо от браузера.

## 2. Структуры данных

### Массивы

Используются для хранения цифр, истории попыток и рекордов.

В функции `generateSecret` массив `availableDigits` содержит доступные цифры, а массив `selectedDigits` хранит уже выбранные цифры секрета.

### Set

Используется для проверки уникальности цифр.

Структура `Set` позволяет определить, встречалась ли цифра ранее.

### Map

Используется для кеширования результатов подсчёта возможных секретов и хранения названий систем счисления.

Пример из `countPossibleSecrets.ts`:

```typescript
const cache = new Map<string, number>();
```

Кеш позволяет повторно использовать уже вычисленные результаты.

### Объекты

Используются для представления результатов попыток и записей таблицы рекордов.

Пример из `evaluateGuess.ts`:

```typescript
return { bulls, cows };
```

Результат содержит два именованных свойства, что делает его удобным для дальнейшего использования.

## 3. Алгоритмы

### evaluateGuess

Сравнивает цифры секрета и попытки по позициям.

Количество быков определяется совпадением цифры и её индекса.

Количество коров определяется наличием цифры в секрете при несовпадении позиции.

Пример реализации:

```typescript
const bulls = guessDigits.filter(
    (digit, index) => digit === secretDigits[index],
).length;

const cows = guessDigits.filter(
    (digit, index) =>
        digit !== secretDigits[index] && secretDigits.includes(digit),
).length;
```

Для секрета длины `n` временная сложность составляет `O(n²)`, поскольку метод `includes` выполняет поиск внутри массива при обходе `guessDigits`.

Дополнительная память: `O(n)`.

### isValidGuess

Проверяет допустимую длину, систему счисления, символы и уникальность цифр.

Временная сложность: `O(n)`.

Дополнительная память: `O(n)`.

### generateSecret

Генерирует секрет, выбирая случайные цифры без повторений из доступного набора.

Функция поддерживает передачу генератора случайных чисел для детерминированного тестирования.

Пример:

```typescript
export function generateSecret(
    length: number,
    base: number,
    random: () => number = Math.random,
): string;
```

Генератор случайных чисел передаётся через параметр `random`.

Выбор цифры:

```typescript
const randomIndex = Math.floor(randomValue * availableDigits.length);

const [digit] = availableDigits.splice(randomIndex, 1);
```

Метод `splice` удаляет выбранную цифру из массива доступных символов, поэтому она не может быть выбрана повторно.

Для используемого массива доступных цифр временная сложность составляет `O(base × length)` в худшем случае.

Дополнительная память: `O(base)`.

### countPossibleSecrets

Вычисляет количество возможных секретов без повторяющихся цифр.

Использует рекурсию и мемоизацию.

Пример:

```typescript
const key = `${length}:${base}`;

const cachedResult = cache.get(key);

if (cachedResult !== undefined) {
    return cachedResult;
}

const result = base * countPossibleSecrets(length - 1, base - 1);

cache.set(key, result);

return result;
```

При первом вычислении функция рекурсивно уменьшает длину и основание системы счисления.

После вычисления результат сохраняется в `Map`.

Для одного нового вызова временная сложность: `O(length)`.

Дополнительная память: `O(length)` для новых записей кеша и стека рекурсии.

Повторный вызов с уже кешированными параметрами выполняется за `O(1)` в среднем.

## 4. Функциональное программирование и Clean Code

В проекте используются функции с явно определёнными параметрами и возвращаемыми значениями, методы массивов `filter` и `every`, функция высшего порядка `createDigitValidator` и передача генератора случайных чисел в `generateSecret`.

### Понятные имена

Названия функций отражают их назначение:

- `generateSecret` генерирует секрет.
- `evaluateGuess` оценивает попытку.
- `isValidGuess` проверяет корректность ввода.
- `countPossibleSecrets` подсчитывает количество возможных секретов.

Такие имена помогают понимать назначение функций без дополнительных комментариев.

### Разделение ответственности

Функция `evaluateGuess` отвечает только за подсчёт быков и коров.

Она получает секрет и попытку, после чего возвращает результат:

```typescript
return { bulls, cows };
```

Функция не изменяет DOM, не сохраняет данные в браузере и не управляет интерфейсом.

Это упрощает тестирование и повторное использование логики.

### Внедрение зависимостей

Функция `generateSecret` принимает генератор случайных чисел через параметр:

```typescript
random: () => (number = Math.random);
```

В обычной игре используется `Math.random`.

Во время тестирования можно передать собственную функцию, возвращающую заранее определённые значения.

Это позволяет проверять результат генерации без зависимости от случайности.

### Использование методов массивов

В `evaluateGuess` применяется метод `filter` для подсчёта совпадений.

Такой подход позволяет выразить условия подсчёта непосредственно в коде без ручного управления счётчиками.

### Отсутствие побочных эффектов в evaluateGuess

Функция не изменяет переданные строки и не обращается к внешнему состоянию.

При одинаковых аргументах она возвращает одинаковый результат.

Это пример чистой функции.

### Разделение логики и интерфейса

Игровые алгоритмы расположены в `src/game`, а работа с DOM находится в `src/main.ts`.

Благодаря этому изменения оформления интерфейса не требуют переписывания алгоритмов подсчёта быков и коров.

## 5. TDD

Разработка игровой логики сопровождалась автоматическими тестами.

Для тестирования используется Vitest.

Тесты проверяют корректные случаи, граничные значения и недопустимые входные данные.

В истории Git имеются отдельные коммиты с тестами и последующей реализацией основных функций.

Это позволяет проверяющему проследить последовательность разработки.

## 6. Инструменты качества

ESLint проверяет код на потенциальные ошибки.

Prettier обеспечивает единый стиль форматирования.

Husky и lint-staged запускают проверки изменённых файлов перед коммитом.

Перед отправкой изменений в GitHub выполняются автоматические тесты.

Для проверки проекта используются команды:

```bash
npm run lint
npm run format:check
npm test
npm run build
```

Автоматические проверки помогают обнаруживать ошибки и поддерживать единый стиль кода.
